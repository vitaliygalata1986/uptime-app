# Frontend

Next.js 16.4.3, React, TypeScript. `/register` — регистрация, `/login` — вход, `/dashboard` — кабинет со списком точек мониторинга. `/` направляет в кабинет. Кнопка «Добавить сайт» открывает форму URL и интервала: целое число и секунды, минуты или часы (например, 7 секунд, 10 минут, 2 часа). После «Создать» точка появляется в списке и сохраняется после перезагрузки. Сам опрос сайтов пока не реализован.

`/dashboard/profile` — просмотр профиля, редактирование имени (1–100 символов) и аватара. Страница открывается из меню пользователя в шапке. Email и дата регистрации доступны только для просмотра. Сохранение только имени вызывает `PATCH /api/auth/profile`, обновляет имя в шапке и сохраняет его в PostgreSQL; перезагрузка читает его через `/me`. «Загрузить аватар» открывает выбор JPEG/PNG (до 5 МБ, до 4096 px по стороне и 16 мегапикселей), затем показывает локальный предпросмотр. «Всё сохранить» отправляет `POST /api/auth/avatar` с multipart-файлом и именем; аватар обновляется в профиле и шапке. Выбор можно отменить до сохранения. Аватар можно загрузить и без имени у нового аккаунта. Кнопка выхода находится справа от профиля.

## Запуск

Нужен Node.js 22.13+ или 24+. Из корня uptime-app: `npm run dev` запускает оба проекта. Для отдельного запуска из frontend:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. `NEXT_PUBLIC_API_URL` по умолчанию равен `http://localhost:8081`. При изменении порта API исправьте `.env.local`. Эти переменные встраиваются при сборке: перезапустите dev-сервер или пересоберите production. Общий launcher задаёт адрес в окружении с приоритетом над `.env.local`.

Backend должен разрешать точный frontend Origin в `ALLOWED_ORIGINS`. Используйте localhost для обоих адресов, не смешивая с 127.0.0.1. Локально нужен `LOCAL_HTTP=true`; при публикации — HTTPS и адреса в пределах одного сайта для `SameSite=Lax`.

## Сессия и структура

`src/lib/auth/api.ts` содержит типы и запросы; `session.ts` управляет состоянием. `src/components/auth/` содержит AuthProvider, AuthGate, формы и кабинет. Refresh хранится в HttpOnly cookie backend; access и срок его действия — только в памяти. Перезагрузка восстанавливает вход через refresh и `/me`. После 401 защищённый запрос обновляется и повторяется не более одного раза. Web Locks сериализует операции между вкладками, BroadcastChannel передаёт только события. Требуется современный браузер, localhost или HTTPS.

Событие входа из другой вкладки сразу скрывает данные прежнего аккаунта до восстановления сессии. Успешные ответы защищённых запросов, включая повтор после 401, отклоняются при смене поколения сессии. Кабинет мониторов создаёт отдельное состояние по ID пользователя: форма находится в `CreateMonitorForm`, загрузка и догрузка — в `useMonitors`. Список загружается по 20 записей; «Показать ещё» использует `next_cursor`, при сбое сохраняет загруженные записи и позволяет повторить страницу. Ошибка квоты 100 точек отображается в форме с сохранением введённых значений.

Сетевой сбой не означает выход: доступен повтор. Неуспешный logout не изображает успешный выход. Клиентский guard управляет UI, авторизацию проверяет Go API. Пользовательские данные не включаются в статический HTML. Access действует 15 минут, refresh-сессия — фиксированные 24 часа. Logout отзывает refresh-сессию, ранее выданный access действует до своего истечения.

## Проверки

```sh
npm run lint
npm test
npm run build
npm start
```

`npm test` использует встроенный Node.js test runner и установленный TypeScript для проверки реального `session.ts`: запоздавшего успешного ответа после выхода, такого же ответа при повторе после 401 и немедленного скрытия данных при событии входа. Постоянный E2E-фреймворк не добавлен. Браузерный чек-лист:

- Регистрация, занятый email, неверный пароль, подтверждение пароля; 15–128 Unicode-символов и сохранение пробелов.
- Гость в кабинете попадает на вход; вход открывает профиль из `/me`.
- Меню открывает `/dashboard/profile`; сохраняются имя и аватар, шапка обновляется, перезагрузка сохраняет значение; ошибки сохранения позволяют повторить запрос.
- Аватар: JPEG/PNG, предпросмотр без загрузки, отмена выбора, отказ для неподходящего формата/размера, ошибка API и повтор, замена изображения и сохранение после перезагрузки.
- Перезагрузка сохраняет сессию; Strict Mode не создаёт конкурентные refresh.
- Истёкший access/один 401: один refresh и повтор; 401 от refresh завершает сессию.
- Выход, повторный вход, недоступный кабинет после выхода; сбой logout позволяет повторить.
- Две вкладки: одновременное восстановление, выход, смена пользователя без гонки refresh.
- Недоступность API, 429 и 5xx; повтор запроса после восстановления.
- Refresh-cookie HttpOnly; токены отсутствуют в localStorage/sessionStorage, UI и логах.
- Мобильный экран, клавиатура, видимый фокус, отсутствие ошибок консоли.
- Точки: пустой список, отмена формы, создание с интервалами в секундах/минутах/часах, отображение сразу и после перезагрузки; некорректный URL, нулевой/дробный интервал, ошибка сохранения и повтор, ошибка списка и повтор. Чужие точки не видны.
- Пагинация: 20 + 20 + остаток без повторов, ошибка следующей страницы и повтор; смена аккаунта в другой вкладке во время GET/POST не возвращает прежние точки в интерфейс.

Проверено 2026-11-05: ESLint, TypeScript и production-сборка; Chrome с отдельными API/PostgreSQL — регистрация, несовпадение паролей, занятый email, неверный пароль, `/me`, HttpOnly и пустые web storage, перезагрузка, одновременное восстановление двух вкладок, синхронизация входа/выхода, мобильный экран 360 px и отсутствие JS-ошибок. Перехватами сетевых запросов проверены один 401 от `/me` с refresh/повтором, 503 от logout с успешным повтором и недоступный refresh с восстановлением после повтора. Реальное ожидание 15 минут/24 часов и ответ 429 в этом браузерном прогоне не проверялись. Общий launcher проверен на том же изолированном окружении через `COMPOSE_FILE`, `COMPOSE_PROJECT_NAME`, `FRONTEND_PORT` и `NEXT_PUBLIC_API_URL`.

## Общая загрузка файлов

`src/lib/uploads.ts` экспортирует `uploadFile(file: File)` и `fileURL(path)`. Функция принимает любой тип файла до 20 MiB, отправляет multipart `file` в `POST /api/uploads` и возвращает `{url, name, size, content_type}`. Авторизация и обновление access-токена используют существующую сессию; Content-Type с boundary задаёт браузер. Общий транспорт находится в `src/lib/api.ts`. Загрузка не меняет профиль пользователя.

```ts
import { uploadFile, fileURL } from "@/lib/uploads";

const uploaded = await uploadFile(file);
const downloadURL = fileURL(uploaded.url);
```

Файлы доступны любому обладателю ссылки и скачиваются как вложения с серверным именем `.bin`; исходное имя есть только в ответе загрузки. Отдельный файловый менеджер в интерфейс не добавлен. Редактор аватара сохраняет проверки JPEG/PNG и отправку только по кнопке «Всё сохранить».
