# Проверка авторизации — 2026-10-30

План [auth-plan.md](auth-plan.md) реализован. Проверяемая цепочка: HTTP-клиент с cookie-файлом → Go API → PostgreSQL → JSON и cookie в ответе. Frontend не входит в этот план, браузерная интеграция не проверялась.

Это исторический отчёт за 2026-10-30: порт `18080` ниже относится к выполненным тогда проверкам. На 2026-11-05 в локальном `backend/.env` задан `API_PORT=8081`, текущая проверка готовности — `http://localhost:8081/healthz`. Значение по умолчанию в Compose и `.env.example` — `8080`, внутри контейнера Go-сервер слушает `8080`. Актуальные команды запуска приведены в [backend/README.md](../backend/README.md).

- API запущен через корневой Compose, от UID/GID `10001:10001`.
- Рабочий адрес проверки 2026-10-30: `http://127.0.0.1:18080`. Тогда порт `8080` был занят другим проектом; значение по умолчанию в Compose оставалось `8080`, локальный `.env` задавал `API_PORT=18080`.

- `backend/.env` создан со случайными секретами, права `0600`; игнорирование проверено через `git check-ignore`. Секреты не включены в документацию.

## Автоматические тесты

Из корня выполнено:

```sh
docker compose -p uptime-auth-tests -f compose.test.yaml up \
  --build --abort-on-container-exit --exit-code-from tests
```

Контейнер завершился с кодом `0`. Он последовательно выполнил сборку, `go vet ./...` и `go test -race -count=1 -v ./...`. Все unit-тесты и девять интеграционных тестов с настоящей PostgreSQL прошли; интеграционные тесты не пропускались.

Подтверждены:

- Валидация конфигурации, email и длины паролей; пароль не обрезается и не нормализуется.
- Argon2id с индивидуальной солью; JWT отклоняет неверные алгоритм, подпись, issuer, audience, истёкший срок, отсутствующий срок/subject и будущее время выпуска.
- Cookie при установке/удалении, `Secure` вне локального режима, CORS/preflight, обязательные Origin/JSON, ограничение тела запроса, лимиты по IP, их конкурентная работа и очистка. Подмена IP через заголовки прокси не работает.
- Миграции на пустой схеме и повторное применение без дублирования версии.
- Регистрация и конкурентная регистрация одного email: один пользователь и одна сессия, остальные запросы получают `409`.
- Вход, одинаковый отказ для неизвестного email и неверного пароля, `/me`, одинаковые публичные данные пользователя после регистрации и чтения из БД.
- Ротация refresh без продления 24 часов, истечение сессии по управляемым тестовым часам.
- Повторное использование старого refresh фиксирует отзыв в БД; новый токен этой сессии тоже отклоняется. Другие устройства продолжают работу.
- Два конкурентных refresh одного токена: один `200`, один `401`, сессия отозвана, история токенов сохранена.
- Идемпотентный logout, удаление cookie, отказ refresh после выхода; access JWT действует до своих 15 минут.
- Ошибка записи refresh при регистрации откатывает пользователя и сессию целиком.

Тестовая PostgreSQL использовала отдельный Compose-проект и `tmpfs`; каждый тест создавал и удалял собственную схему. После проверки временные контейнеры и сеть удалены командой `docker compose -p uptime-auth-tests -f compose.test.yaml down`.

## Проверки живого HTTP и постоянных данных

Из `backend/` выполнен `scripts/http_smoke.py` с `--url http://127.0.0.1:18080`. Cookie записываются в файл с правами `0600` после каждого ответа; значения токенов не печатаются.

| Запрос | Фактический статус |
| --- | --- |
| `GET /healthz` | `200` |
| `POST /api/auth/register` | `201` |
| `GET /api/auth/me` с access JWT | `200` |
| `POST /api/auth/refresh` с cookie | `200` |
| `POST /api/auth/logout` | `204` |
| Повторный logout | `204` |
| Refresh после logout | `401` |
| `/me` с ещё действующим access JWT после logout | `200` |
| Повторный вход | `200` |

Фаза `prepare` сохранила пользователя, access JWT и refresh-cookie в закрытом временном каталоге. Затем выполнены `docker compose --env-file backend/.env down` и `up -d`, без удаления volume. После пересоздания контейнеров фаза `verify` подтвердила того же пользователя через `/me` и успешный refresh сохранённой сессии. После проверки сессия завершена, временные файлы токенов удалены.

В PostgreSQL после пересоздания остались записи Goose: версии `0` и `1`, обе применены; повторного применения версии `1` нет. По завершении проверки 2026-10-30 API и основная БД были оставлены запущенными на указанном выше адресе. Тестовые HTTP-пользователи были оставлены только в локальной БД.

HTTPS и браузерный frontend не проверялись. Флаги production-cookie проверены unit-тестами; frontend авторизации, подтверждение email и восстановление пароля остаются вне согласованного объёма.
