# Авторизация Go API с GORM и PostgreSQL

## Результат и выбор ORM

Использовать **GORM** с пакетами `gorm.io/gorm` и `gorm.io/driver/postgres`. У него есть официальный PostgreSQL-драйвер на основе pgx, транзакции и блокировки строк, необходимые для безопасного обновления refresh-токенов. [Подключение PostgreSQL](https://gorm.io/docs/connecting_to_the_database.html#PostgreSQL), [блокировки](https://gorm.io/docs/advanced_query.html#Locking).

Реализовать регистрацию и вход по email и паролю, обновление токенов, выход и получение текущего пользователя. API и PostgreSQL запускаются через Docker Compose.

**Access JWT действует 15 минут, refresh-сессия — 24 часа с момента входа.** Обновление токенов не продлевает эти сутки. Фронтенд, подтверждение email и восстановление пароля в задачу не входят.

## API

| Метод и маршрут | Поведение |
|---|---|
| `POST /api/auth/register` | Принимает `email`, `password`; создаёт пользователя и авторизует; ответ `201` |
| `POST /api/auth/login` | Принимает `email`, `password`; создаёт отдельную сессию; ответ `200` |
| `POST /api/auth/refresh` | Получает refresh из cookie и выдаёт новую пару токенов; ответ `200` |
| `POST /api/auth/logout` | Отзывает текущую refresh-сессию и удаляет cookie; ответ `204` |
| `GET /api/auth/me` | Проверяет `Authorization: Bearer <JWT>` и возвращает пользователя |

Регистрация, вход и refresh возвращают JSON с `user`, `access_token`, `token_type: "Bearer"` и `expires_in` в секундах. Публичные данные пользователя: `id`, `email`, `created_at`. Refresh передаётся только через `Set-Cookie`.

Формат ошибок: `{error: {code, message}}`. Статусы: некорректный запрос — `400`, неверные учётные данные или токены — `401`, запрещённый Origin — `403`, занятый email — `409`, превышение лимита — `429`. Ошибка входа не раскрывает, существует ли email.

## Реализация и хранение данных

- Использовать Go 1.27, стандартный `net/http`, GORM и `golang-jwt/jwt/v5`. Разделить HTTP-обработчики, авторизацию, хранилище и конфигурацию внутри `backend/internal/`.
- Добавить GORM-модели `User`, `AuthSession`, `RefreshToken`. Работу с ORM сосредоточить в слое хранилища; для запросов и ответов API использовать отдельные структуры без хешей паролей и токенов.
- Схему вести через версионированные SQL-миграции Goose. GORM и Goose используют общий пул `*sql.DB`; `AutoMigrate` не вызывать. Миграции выполнять перед запуском HTTP-сервера; при ошибке завершать запуск. [Доступ к пулу GORM](https://gorm.io/docs/generic_interface.html).
- Email очищать от пробелов по краям и приводить к нижнему регистру. Уникальность email и хеша refresh обеспечить ограничениями БД; добавить внешние ключи и индекс связи токенов с сессией.
- Пароль принимать длиной 8–128 символов без изменения. Хешировать Argon2id с индивидуальной солью: память 19 MiB, две итерации, параллелизм 1. [Рекомендации OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- Подписывать access JWT алгоритмом HS256; проверять алгоритм, подпись, срок, issuer и audience. Секрет из окружения — минимум 32 случайных байта; некорректная конфигурация блокирует запуск.
- Refresh создавать из 32 криптографически случайных байтов; хранить только SHA-256-хеш. Регистрацию с созданием сессии и каждую ротацию выполнять атомарно.
- При refresh использовать GORM-транзакцию и `SELECT … FOR UPDATE` для строки сессии; после блокировки повторно проверять состояние токена. Погашение старого и создание нового токена фиксировать одной транзакцией.
- Повторное использование погашенного refresh отзывает соответствующую сессию; другие устройства сохраняют свои сессии. Отзыв обязательно закоммитить перед возвратом `401`: возврат ошибки из callback GORM откатывает транзакцию. Историю токенов сохранять до истечения сессии. [Транзакции GORM](https://gorm.io/docs/transactions.html), [ротация refresh-токенов](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14).
- Cookie: `HttpOnly`, `SameSite=Lax`, `Path=/api/auth`, без `Domain`; срок соответствует остатку сессии. `Secure` обязателен вне локального HTTP-режима.
- Для POST-запросов авторизации требовать `application/json` и разрешённый `Origin`; refresh/logout принимают `{}`. CORS разрешает credentials только указанным origin, локально — `http://localhost:3000`.
- Ограничить запросы на IP: регистрация — 5, вход — 10, refresh — 30 в минуту. Устаревшие записи лимитера очищать; заголовкам прокси по умолчанию не доверять.
- Logout сделать идемпотентным. Access JWT после выхода остаётся действительным до истечения, максимум 15 минут.
