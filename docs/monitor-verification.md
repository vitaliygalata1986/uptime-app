# Проверка создания точек мониторинга

Проверено 2026-11-11. Сценарий: «Добавить сайт» → URL и интервал → `POST /api/monitors` → PostgreSQL → список в кабинете и после перезагрузки. Опрос сайтов в задачу не входит.

## Автоматические проверки

Из `backend/`:

```sh
docker compose -p uptime-auth-tests -f ../compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
```

Прошли `go build`, `go vet`, `go test -race -count=1 -v ./...`. Интеграционные тесты выполнялись в отдельных схемах тестовой PostgreSQL, без данных приложения. Добавлены проверки URL и интервалов, создания и чтения реальных записей, порядка списка, пустого списка, изоляции пользователей, неизвестных полей, отсутствующего/неверного/истёкшего JWT, CORS и методов GET/POST/OPTIONS. Тесты миграций профиля и аватара обновлены с учётом новой таблицы.

Из `frontend/`: `npm run lint` и `npm run build` на Node.js 24.6.0. TypeScript и production-сборка прошли. `git diff --check` прошёл.

## Проверка Chrome

Использованы временные Next.js на `localhost:3100`, API на `localhost:18081` и отдельная PostgreSQL из `compose.test.yaml`. Проверка выполнена Playwright с установленным Chrome; зависимости для неё установлены только в `/tmp`, конфигурация тестового фреймворка проекта не менялась.

Подтверждены:

- Регистрация и пустой список; открытие и отмена формы, фокус после закрытия.
- Создание с 7 секундами, 10 минутами и 2 часами. В HTTP-ответах и БД интервалы равны `7`, `600` и `7200` секундам.
- Отклонение неправильного URL, FTP, нуля, отрицательного, дробного и слишком большого интервала. Некорректные значения не создают точек.
- Ошибка `503` при создании: введённые значения сохраняются, повтор создаёт одну точку. Одновременные отправки формы создают ровно одну точку.
- Ошибка `503` при загрузке списка и успешная кнопка «Повторить загрузку».
- Пять созданных точек отображаются сразу и после перезагрузки, а после перезапуска API видны при повторном входе. Проверены реальные строки в тестовой БД.
- Новый пользователь не видит точки первого пользователя.
- Экран 360 px без горизонтального переполнения; нет необработанных JS-ошибок, web storage остаётся пустым.

В кабинете указан статус «Опрос ещё не запущен»; метрики доступности не отображаются. Для защищённой страницы, которую клиентский auth guard показывает после восстановления сессии, задан `instant = false` согласно локальной документации Next.js 16.4.3. Это устраняет предупреждение проверки instant navigation без изменения авторизации.
